# 4×4 Magic Square — 문제 정의 보고서

**작성일**: 2026-05-28  
**단계**: STEP 1 ~ STEP 5 (문제 인식 및 정의 완료)  
**목적**: 구현에 앞선 문제 정의 프로세스의 결과물

---

## 개요

본 보고서는 4×4 마방진 프로그램을 구현하기에 앞서,
"무엇을 만들 것인가"가 아닌 **"무엇이 참이어야 하는가"** 를 먼저 정의하기 위해
다섯 단계의 문제 인식 프로세스를 수행한 결과를 담고 있다.

---

## STEP 1 — Observation (관찰)

### 현재 상황
- 4행 4열, 총 16개의 칸으로 구성된 격자가 존재한다.
- 각 칸에는 1부터 16까지의 자연수가 정확히 한 번씩 배치되어야 한다.
- 가로 합, 세로 합, 두 대각선 합이 모두 동일한 값을 가져야 한다.
- 이 상황은 **제약 조건이 강한 배치(constraint-heavy arrangement)** 문제이다.
- 탐색 공간: 16! ≈ 2 × 10¹³ (무작위 시도로 도달 불가)

### 왜 4×4인가
- 3×3: 해가 본질적으로 1개 → 학습 가치 제한적
- 4×4: 해가 880개 → 패턴·구조·대칭성 관찰에 최적
- 5×5 이상: 상태 공간 과대 → 분석 어려움
- **수학적 구조 + 알고리즘적 탐색 + 시스템 설계가 한 점에서 만나는 최적 크기**

### 등장 맥락
| 맥락 | 내용 |
|---|---|
| 학습적 | 문제 분해, 불변식 사고, 알고리즘 패러다임 비교 |
| 시스템 설계 | 도메인 모델링, 책임 분리, 테스트 가능성 훈련 |
| 산업적 | CSP(Constraint Satisfaction Problem) 계열 시스템의 입문 사례 |

## STEP 2 — Why #1 (첫 번째 왜)

**Q: 왜 마방진을 완성해야 하는가?**

### 가정된 답
> "모든 행·열·대각선의 합이 동일한 균형 잡힌 상태를 한 번이라도 명확히 실현해 보기 위해서이다."

### 이 답에서 드러난 불편함

| 불편함 | 내용 |
|---|---|
| ① | "완성"의 정의가 모호하다 — 1개인가, 880개 전체인가? |
| ② | "완성"은 목적이 아니라 결과일 뿐이다 |
| ③ | "완성"은 검증 책임을 은폐한다 |
| ④ | "완성"은 해 공간(solution space)을 가린다 |

### 구조적 문제
- 목적과 수단의 혼동
- 성공 기준(Success Criteria)의 부재
- 문제(Problem)와 해(Solution)의 경계 붕괴
- 재사용성과 확장성의 단절

## STEP 3 — Why #2 (두 번째 왜)

**Q: 왜 단순 계산이 아니라 프로그램으로 구현하는가?**

| 관점 | 드러난 본질 |
|---|---|
| **반복 가능성** | 프로그램은 논리를 저장한다. 손 계산은 결과만 저장한다. |
| **검증 자동화** | 인간의 주의력 한계를 시스템으로 보완한다. 10가지 조건을 빠짐없이 실행한다. |
| **오류 방지** | 오류를 사후에 발견하는 것이 아니라, 오류가 발생할 구조 자체를 설계로 제거한다. |
| **규칙 기반 사고** | "내가 이 문제를 이해한다"는 주장을 실행 가능한 형태로 증명하는 과정이다. |

### 핵심 발견
> 프로그램으로 구현한다는 것은,
> 머릿속에 있는 모호한 이해를 실행 가능하고 검증 가능한 명확한 논리로 변환하는 행위이다.

## STEP 4 — Why #3 (세 번째 왜, 핵심 발견)

**Q: 왜 이 문제를 TDD 방식으로 설계하려 하는가?**

### 무엇이 통제되어야 하는가
| 통제 대상 | 마방진에서의 의미 |
|---|---|
| 정확성(Correctness) | 각 조건이 코드로 선언된다 |
| 완전성(Completeness) | 행·열·대각선·중복 각각을 독립적으로 검증한다 |
| 회귀(Regression) | 알고리즘 교체 후에도 동일한 검증이 유효하다 |

> 통제란 결과를 제어하는 것이 아니라, 이해의 경계를 명확히 하는 것이다.

### 불변 조건의 계층
```
Level 0 — 구성 불변 조건
  └── 16칸, 1~16, 중복 없음

Level 1 — 합산 불변 조건
  └── 행·열·주 대각선·반 대각선 각각의 합 = 34 (서로 독립)

Level 2 — 파생 불변 조건
  └── 34 = n(n²+1)/2  →  격자 크기 n이 결정되면 유일하게 결정됨

Level 3 — 설계 불변 조건
  └── 생성·검증·표현은 서로 독립적이어야 한다
```

### 왜 입력/출력이 명확해야 하는가
- 책임의 명확화: generate / validate / display 의 자연스러운 분리
- 테스트 가능성 확보: 반환값이 없으면 검증이 불가능하다
- 이해의 증명: 입력/출력을 명확히 정의하지 못하면 그 기능을 아직 이해하지 못한 것이다

### TDD가 필연적인 이유
```
STEP 1  →  제약 조건이 강한 배치 문제
STEP 2  →  "완성"이라는 목표는 성공 기준을 은폐한다
STEP 3  →  프로그램만이 반복·검증·방지·규칙화를 실현한다
STEP 4  →  TDD만이 불변 조건을 먼저 선언하고 이해를 증명한다
```

## STEP 5 — 진짜 문제 정의

### 표면 문제 정의 (잘못된 정의)
> "1부터 16까지의 숫자를 4×4 격자에 배치하여,
> 모든 행·열·대각선의 합이 같아지는 마방진을 만드는 프로그램을 작성한다."

**결함 목록**
| 결함 | 설명 |
|---|---|
| 목적의 부재 | "만든다"는 동사가 목적을 설명하지 않는다 |
| 성공 기준의 부재 | 언제 완성된 것인가? |
| 검증의 은폐 | "합이 같아지는"은 검증 책임의 명시가 아니다 |
| 해 공간의 무시 | 880개의 해가 단수 표현으로 사라진다 |
| 불변 조건의 생략 | 34라는 값의 유도 근거가 숨겨진다 |
| 수단과 목적의 혼동 | 구현이 목적으로 위장된다 |

---

### 개선된 문제 정의 (정확한 정의)

> **"4×4 격자 위에서, 1부터 16까지의 자연수를 중복 없이 배치하였을 때,**
> **모든 행(4개), 모든 열(4개), 두 대각선(2개)의 합이**
> **동일한 값(Magic Constant = 34)을 만족하는 상태가 존재하는가를 판단하고,**
> **그 상태를 생성·검증·표현하는 각각의 책임을 명확히 분리하여 다룰 수 있는가."**

---

### 핵심 Invariant

#### Level 0 — 구성 불변 조건
- 격자는 정확히 4행 4열, 총 16칸으로 구성된다.
- 사용 숫자는 1 이상 16 이하의 자연수이며, 각 숫자는 정확히 한 번만 등장한다.
- 이 두 조건은 전체 조건의 전제이다.

#### Level 1 — 합산 불변 조건
- **행(Row) 불변**: 4개의 행 각각의 합 = **34**
- **열(Column) 불변**: 4개의 열 각각의 합 = **34**
- **주 대각선 불변**: 좌상 → 우하 방향 4개의 합 = **34**
- **반 대각선 불변**: 우상 → 좌하 방향 4개의 합 = **34**
- **이 네 조건은 서로 독립이다. 각각 별도로 성립해야 한다.**

#### Level 2 — 파생 불변 조건
- Magic Constant = **n(n² + 1) / 2**
- 4×4의 경우: **4 × (16 + 1) / 2 = 34**
- 34는 1~16의 총합(136)을 4등분한 값이기도 하다.
- 격자 크기 n이 결정되는 순간 Magic Constant는 유일하게 결정된다.

#### Level 3 — 설계 불변 조건
- 생성(Generation)과 검증(Validation)은 서로 독립적이어야 한다.
- 검증은 생성 방식을 알지 못해야 한다.
- 표현(Representation)은 생성과 검증 어느 쪽도 의존하지 않는다.

### 우리가 실제로 훈련하려는 사고 능력

| 사고 능력 | 설명 |
|---|---|
| **조건의 완전한 열거** | 행만이 아닌 열·대각선·중복·범위까지 빠짐없이 나열하는 능력 |
| **불변 조건의 선언** | "어떻게 만들까"보다 "무엇이 반드시 참이어야 하는가"를 먼저 묻는 능력 |
| **책임의 분리** | 생성·검증·표현이 서로 다른 관심사임을 인식하고 분리하는 능력 |
| **표면과 본질의 구분** | "마방진을 만든다"와 "제약 조건을 만족하는 상태를 판단한다"의 차이를 인식하는 능력 |
| **성공 기준의 사전 정의** | 작업 시작 전 "언제 완성된 것인가"를 먼저 선언하는 능력 |

## 종합 구조도

```
표면 문제     →  마방진 한 장을 완성하는 것
              ↕ (전환)
진짜 문제     →  제약 조건의 완전한 집합을 먼저 선언하고,
               그것을 독립적으로 생성·검증·표현할 수 있는
               시스템을 설계할 수 있는가

핵심 Invariant
  Level 0: 구성 조건 (16칸, 1~16, 중복 없음)
  Level 1: 합산 조건 (행·열·대각선 = 34, 각각 독립)
  Level 2: 파생 조건 (34는 n에 의해 결정된다)
  Level 3: 설계 조건 (생성·검증·표현은 분리된다)

훈련 목표
  조건 열거 · 불변 선언 · 책임 분리 · 표면/본질 구분 · 성공 기준 사전 정의
```
