# User 도메인 확장 보고서 (STEP 5 보강)

> 기존 `Report/problem-definition-report.md` (STEP 1~5)의 후속 산출물.
> "구현보다 먼저, 정의가 있다"는 본 프로젝트 원칙에 따라
> `User` 객체를 도메인에 편입시키기 전 정당성·책임·불변 조건을 선언한다.

---

## 0. 작성 배경

기존 STEP 5에서 정의된 도메인 객체는 다음과 같다.

```
entity/ ─ Grid, Cell, constants  (Magic Constant = 34 도메인)
```

`User`는 위 어느 객체에도, 어느 Invariant Level(0~3)에도 등장하지 않는다.
따라서 `User`를 그대로 `entity/`에 추가하면 ECB 경계와 도메인 정의 양쪽을 위반한다.

본 보고서는 이 위반을 회피하기 위해, `User`를 **도메인 의도와 일관된 방식**으로
편입시키는 정당성 근거를 STEP 5 형식(표면 정의 / 개선된 정의 / Invariant / 훈련 목표)으로 기록한다.

---

## 1. 표면 문제 정의 (잘못된 정의)

> "사용자 계정 정보(아이디, 이름, 비밀번호 등)를 저장하기 위한 객체."

이 정의가 문제인 이유:

| 문제 | 근거 |
|---|---|
| 도메인 무관 | 마방진 도메인의 어떤 Invariant도 사용자 계정에 의존하지 않는다 |
| 책임 혼재 | 인증·세션·프로필을 한 객체에 묶으면 ECB 경계 붕괴 |
| 표면적 명명 | "User"라는 일반 명사는 도메인 의도를 가리는 매직 단어 |

---

## 2. 개선된 문제 정의 (정확한 정의)

> **마방진 도메인에서 `User`는 "해를 탐색·제출한 주체로서, 본인이 제출한 해의 귀속(attribution)을 식별 가능하게 하는 도메인 객체"이다.**

즉 `User`는 다음 세 가지를 충족할 때에만 도메인에 편입된다.

1. `User`는 마방진 해(Grid)의 **생성·검증 로직과 독립**이다 (Level 3 유지)
2. `User`는 해의 **귀속(attribution)** 만 식별 가능하게 한다 — 해의 정당성과는 무관
3. `User`는 **순수 도메인 객체**로서 외부 의존(파일·DB·세션·CLI)을 갖지 않는다

이 정의를 만족하지 못하면 `User`는 entity가 아닌 boundary 객체로 재분류되어야 한다.

---

## 3. Level 4 — `User` Invariants (신규)

기존 Level 0~3에 다음 Level 4를 추가한다.

### Level 4 — 귀속(Attribution) Invariants

| 식별자 | 조건 | 위반 시 |
|---|---|---|
| **Identity-1** | `user_id`는 비어 있지 않은 문자열이다 | 생성 거부 |
| **Identity-2** | `user_id`는 공백만으로 구성되지 않는다 | 생성 거부 |
| **Identity-3** | `name`은 비어 있지 않은 문자열이다 | 생성 거부 |
| **Identity-4** | `name`은 공백만으로 구성되지 않는다 | 생성 거부 |
| **Identity-5** | `user_id`는 생성 후 변경 불가하다 (불변성) | 재할당 거부 |
| **Identity-6** | 두 `User` 인스턴스의 동등성은 `user_id`로만 결정된다 | 값 동등성 |
| **Identity-7** | `User`는 해시 가능하다 (set/dict 키 사용 가능) | 도메인 사용 제약 |

### 의도적으로 배제된 책임

| 배제된 책임 | 배제 이유 | 위임 대상 |
|---|---|---|
| 인증·비밀번호 | 도메인 외 관심사 | 향후 boundary 또는 별도 컨텍스트 |
| 해(Grid) 보유·이력 관리 | 단일 책임 원칙 (SRP) 위배 위험 | 향후 `Submission` / `Attempt` 엔티티 (별도 도입) |
| 직렬화·파일 입출력 | ECB 경계 위반 | boundary 레이어 |

## 4. ECB 레이어 판정

| 판정 항목 | 결과 |
|---|---|
| 외부 입출력 의존 | 없음 |
| `control` 또는 `boundary` 모듈에 대한 import 의존 | 없음 |
| 다른 도메인 객체(`Grid`, `Cell`)에 대한 의존 | 없음 (독립) |
| 도메인 불변 조건의 보유 | Identity-1 ~ Identity-7 |
| **결론** | **`entity/` 레이어 (`magic_square/entity/user.py`)** |

`.cursorrules`의 `allowed_imports: []` 규칙에 부합한다.

## 5. 훈련 목표와의 연결

기존 훈련 목표 5가지에 본 확장이 부합하는지 검토.

| 훈련 목표 | 본 확장에서의 의미 |
|---|---|
| 조건의 완전한 열거 | Identity-1 ~ Identity-7로 식별·동등성·불변성을 분리 열거 |
| 불변 조건의 선언 | "User가 무엇을 할 수 있나"보다 "User에 무엇이 참이어야 하나"를 먼저 |
| 책임의 분리 | 인증·이력·직렬화를 의도적으로 배제하여 도메인 단일 책임 보존 |
| 표면과 본질의 구분 | "사용자 정보 저장"(표면) vs "해의 귀속 식별"(본질) |
| 성공 기준의 사전 정의 | Identity-1~7 위반 시 생성 거부 — RED 단계에서 명시적 검증 |
